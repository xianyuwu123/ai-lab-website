    每个中断：优先级、挂起状态与等待原因

    数值越小，优先级越高
    中断源 / IRQn抢占优先级副优先级逻辑值 / IPR 编码源标志NVIC 使能PendingActive当前判断

    EXTI_PR 与 NVIC Pending 是不同层级的状态。进入 ISR 时，NVIC 接受请求并转为 Active；EXTI_PR 仍需软件写 1 清除。PR 用位记录请求，多次触发不等同于排队计数。

    自由实验：触发请求、改变屏蔽条件，再让 CPU 作出判断

    产生请求

    EXTI 按钮产生一次所配置的下降沿；TIM2 按钮模拟一次更新请求。按钮只产生请求，随后点击“仲裁一次”观察响应。

    可先点“结束当前 ISR”而不清源标志，观察请求再次出现。普通 ISR 返回自动清 FAULTMASK，NMI 返回不自动清它。

    屏蔽条件

    多个屏蔽条件共同生效。取消其中一个条件，不代表其他条件也取消。BASEPRI 选项按当前抢占分组边界对齐，便于比较。

    调整优先级 / NVIC 使能

    请在主程序且无挂起请求时调整优先级，以便从清晰的起点比较；未使能不等于没有 Pending。

    屏蔽对照：BASEPRI、PRIMASK、FAULTMASK 分别挡住谁？

    下表仅比较屏蔽条件，假设请求已经使能、CPU 没有执行同级或更高优先级异常。第 3 例使用 4 位抢占、0 位副优先级。

    请求全部为 0仅 BASEPRI=0x80仅 PRIMASK=1仅 FAULTMASK=1当前实际屏蔽条件

    BASEPRI=0x80 对应逻辑阈值 8：允许 0—7，屏蔽 8—15；BASEPRI=0 表示取消阈值屏蔽。写 __set_BASEPRI(8) 与写 __set_BASEPRI(0x80) 不同，STM32F103 使用高四位，前者不会得到阈值 8。

    PRIMASK 不屏蔽 NMI、HardFault。FAULTMASK 可以阻止 HardFault 进入，只留下 NMI；复位另行处理。同步故障的升级和 Lockup 不按普通中断排队模拟，本页只用对照表说明 HardFault 的屏蔽关系。

    优先级编码与分组：为什么 CMSIS 参数和寄存器值不一样？

    先分出抢占位和副优先级位

    库分组名抢占位数副位数AIRCR.PRIGROUP
    PriorityGroup_0047
    PriorityGroup_1136
    PriorityGroup_2225
    PriorityGroup_3314
    PriorityGroup_4403

    STM32F103 实现 IPR[7:4]，共有 4 个有效优先级位；IPR[3:0] 未实现。库中“第 2 组”与 AIRCR.PRIGROUP=2 不是同一个编号。分组可由特权软件改写，实际工程通常统一在初始化阶段设置。

    第 2 例：TIM2 抢占 2、副 3

    10110000

    高两位 10 表示抢占 2，接下来的 11 表示副 3。逻辑值为 (2 << 2) | 3 = 11，写入 IPR 后为 0xB0。

    NVIC_SetPriorityGrouping(5); // 2 抢占位 + 2 副位
uint32_t p = NVIC_EncodePriority(5, 2, 3); // p = 11
NVIC_SetPriority(TIM2_IRQn, p); // CMSIS 内部左移

// BASEPRI 则直接使用左对齐的寄存器编码
__set_BASEPRI(0x80);

    抢占只比较抢占字段；多个可响应请求一起等待时，依次比较抢占字段、副字段、异常号。优先级完全相同的外部 IRQ，IRQn 更小者先响应。

    EXTI 配置路线与常见误解

    PA0 到 EXTI0 的配置

    打开 GPIOA、AFIO 时钟，配置 PA0 上拉输入；用 AFIO_EXTICR1 选择 PA0 连接 EXTI0；设置 FTSR0=1、RTSR0=0；清除旧 PR0，设置 IMR0=1；最后配置并使能 NVIC 的 EXTI0 通道。

    PA0、PB0、PC0 等共用 EXTI0 的选择位置，一条 EXTI 线同一时刻只能选择其中一个端口。EXTI0—4 各自有 IRQ，EXTI5—9 与 EXTI10—15 分组共享 IRQ。TIM2 有自己的中断通道，不经过 GPIO 的 EXTI 路径。

    PR 的“写 1 清除”

    if (EXTI->PR & (1u << 0)) {
    EXTI->PR = (1u << 0); // 写 1 清除 PR0
    // 执行按键响应
}

    不要用 EXTI->PR |= mask 清位：读改写可能将读到的其他 1 也写回，从而一并清掉其他挂起位。NVIC_ClearPendingIRQ 清的是 NVIC 层，不能替代清除 EXTI_PR。

    中断路径与事件路径

    IMR 控制中断请求路径，EMR 控制事件脉冲路径。事件可以参与唤醒等硬件机制，不等同于进入 ISR。本页三个案例都使用中断模式（EMR=0），不模拟 WFE / WFI 和事件寄存器。

    采用 STM32F103VET6 的 4 位优先级，PA0—PA2 为上拉、下降沿触发；PE0—PE2 的高电平有效 LED 用来显示各 EXTI ISR 的处理动作。引脚接线以教学示意为准。按键已视为消抖后的单次边沿。
