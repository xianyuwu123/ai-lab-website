## 一、中断的基本概念

### 1.1 中断的定义与意义

**中断（Interrupt）**：CPU 暂时中止其正在执行的程序，转去执行请求中断的那个外设或事件的服务程序，等处理完毕后再返回执行原来中止的程序，称为中断。

为什么要设置中断？有 5 个核心理由：

1. **提高 CPU 工作效率**：不必花大量时间等待和查询外设；
2. **实时处理功能**：现场参数和状态要求 CPU 快速响应、及时处理；
3. **故障处理功能**：可以执行处理故障的中断服务程序；
4. **低功耗设计**：CPU 空闲时进入低功耗模式，由中断事件唤醒；
5. **分时操作**：控制多个外设同时工作。

生活类比：等快递时反复看手机是「轮询」，快递员按门铃通知是「中断」——中断让 CPU 不必空转等待。

### 1.2 中断源与中断标志

**中断源**：引发中断的事件，通常与外设有关。常见中断源有按键按下 / 释放、定时器溢出、串口收到数据等，对应的外设有键盘、定时器、串口。按来源可分为：输入 / 输出设备中断源、故障中断源、实时中断源、定时 / 计数脉冲中断源。

两个关键机制：

- **中断请求标志位**：每个中断源都有对应的标志位，中断发生即置位；标志位清除后该中断不再被响应，所以一般在中断服务程序末尾要把对应标志清零。
- **中断屏蔽位**：通过设置屏蔽位，禁止 CPU 响应某个中断。
- **可屏蔽中断 vs 不可屏蔽中断（NMI，Non Maskable Interrupt，不可屏蔽中断）**：电源故障、内存出错、总线出错等属于不可屏蔽中断，CPU 不能屏蔽。

### 1.3 中断处理过程与中断服务程序

中断处理流程分四步：**中断请求 → 中断响应 → 中断服务（ISR，Interrupt Service Routine，中断服务程序） → 中断返回**。

在 Cortex-M3 中，硬件自动完成现场保护：

1. 硬件自动将 PC（程序计数器）、XPSR（程序状态寄存器）、LR（链接寄存器）和通用寄存器 R0~R3、R12 等压入堆栈；
2. 通过数据总线（Dbus）保存处理器状态，同时通过指令总线（Ibus）从中断向量表识别异常向量、获取 ISR 地址（保护现场与取向量并行）；
3. 中断服务程序或故障处理程序开始执行；
4. 硬件出栈，恢复现场；
5. 中断返回，程序正常执行。

**中断服务程序（ISR）的特点**：

- 没有参数、没有返回值，也不由用户调用，而是由硬件在中断发生时自动调用；
- 在 ISR 中修改其他程序访问的变量，定义和声明时前面要加 `volatile` 修饰；
- 应当尽量简短。

**为什么 ISR 里的变量要加 `volatile`**

`volatile` 本意是「易变的、易挥发的」。它的作用是把变量标识为「变化中的」——即使主线程没有任何存取操作，该变量也可能被其他线程 / 中断改变。因为访问寄存器比访问内存快得多，编译器会做减少内存存取的优化，可能读到脏数据；声明 `volatile` 后，每次读写都直接从变量地址取数，避免不一致。

### 1.4 案例：轮询与中断检测按键

轮询方式（`while(1)` 反复读引脚）会阻塞其他任务；中断方式由硬件通知 CPU，主循环不被卡死：

```c
// 轮询检测按键（可能阻塞网络等其它任务）
while (1) {
  if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_SET) {
    HAL_Delay(10); // 简单防抖
  }
}

// 中断方式：硬件自动调用，主循环不被阻塞
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
  if (GPIO_Pin == GPIO_PIN_0) {
    HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_5); // 翻转 LED
  }
}
```

延伸思考（课件讨论题）：共享单车锁控若用轮询检测开锁信号，会浪费 CPU 且响应慢；四旋翼飞控中「保持飞行稳定（中断 1）」和「记录日志（中断 2）」同时发生，则需要靠**中断嵌套**解决——高优先级中断可打断低优先级中断。

## 二、STM32 的中断管理

### 2.1 STM32 的中断源

按来源，中断分为：

- **外部中断**：由计算机外设发出的中断请求，如键盘中断、定时器中断，可用中断控制器屏蔽；
- **内部中断**：由硬件出错（掉电、奇偶校验错）或运算出错（除零、溢出、单步）引起；
- **软件中断**：并非真正中断，只是可被调用的一般程序（如 DOS 的 INT 21H）。

Cortex-M3、STM32 系列、STM32F103VET6 三者的中断资源对比：

| 项目 | Cortex-M3 处理器 | STM32 系列芯片 | STM32F103VET6 |
| --- | --- | --- | --- |
| 系统异常（内部） | 1~15 | 1~15 | 1~15 |
| 外部中断 | 240 | 68 | 60 |
| 可编程优先级 | 256 | 16 | 16 |

要点：

- **NMI（Non Maskable Interrupt，不可屏蔽中断）**：通知 CPU 发生「灾难性」事件（电源掉电、存储器读写出错、总线奇偶位出错），边沿触发、不可屏蔽、立即锁存。
- **中断向量表**：STM32F103 各中断的 ISR 入口地址统一存放在向量表中，一般位于存储器 0 地址处；向量地址 = 向量编号 × 4。前 15 个异常号已分配给系统异常，所以中断 0 的异常号是 16。

### 2.2 STM32 的中断优先级

**NVIC（Nested Vectored Interrupt Controller，嵌套向量中断控制器）** 是 Cortex-M3 不可分离的一部分。STM32F103VET6 仅有 60 个可屏蔽中断通道（不含 Cortex-M3 的 16 条中断线）和 16 级优先级。

STM32F103 的中断有两个优先级概念：

- **抢占式优先级（pre-emption priority，也叫组优先级）**：低抢占式优先级处理过程中，高抢占式优先级可响应，形成中断嵌套；
- **副优先级（sub-priority）**：抢占式优先级相同时，高副优先级优先被响应；但若低副优先级正在执行，高副优先级要等它结束才能响应（不能嵌套）。

**优先级冲突处理规则**：先看抢占优先级（决定是否嵌套），再看副优先级。若两者都相同，按中断表中的排位顺序决定。

**优先级分组**（STM32 用 4 位优先级寄存器中的高 4 位，分 5 组）：

| 组 | 抢占优先级位数 | 副优先级位数 |
| --- | --- | --- |
| 第 0 组 | 0 位（无） | 4 位（全用于副优先级） |
| 第 1 组 | 1 位 | 3 位 |
| 第 2 组 | 2 位 | 2 位 |
| 第 3 组 | 3 位 | 1 位 |
| 第 4 组 | 4 位（全用于抢占） | 0 位（无） |

### 2.3 向量中断寄存器与中断屏蔽

NVIC 的访问基地址是 **0xE000 E000**（注意与中断向量表地址不同）。NVIC 的中断控制 / 状态寄存器只能在**特权级**下访问（仅软件触发中断寄存器可在用户级访问）。

每个外部中断涉及这些寄存器族：**使能与除能寄存器（SETENA/CLRENA）**、**挂起与解挂寄存器（SETPEND/CLRPEND）**、**优先级寄存器**、**活动状态寄存器**。

- **使能 / 除能**：写 1 到 SETENA 使能、写 1 到 CLRENA 除能；写 0 无效（这样一次只需写目标位为 1，其它位可为 0，不会误改其它中断）。
- **挂起与解挂**：中断发生时若正在处理同级 / 高优先级或被屏蔽，就进入挂起状态，记录在挂起寄存器中；向 CLRPEND 写 1 可清除挂起（解挂）。类比：病人（中断）来医院（CPU），医生正忙则去等候区（挂起）排队，护士叫号（解挂）后进入诊室。
- **优先级寄存器**：每中断占 8 位，STM32 只用高 4 位（bits[7:4]），数值越小优先级越高。根据分组划分抢占 / 副优先级两段。
- **活动状态位**：执行 ISR 第一条指令后置 1，直到 ISR 返回才硬件清零；支持嵌套时即便被抢占，活动位仍为 1。
- **优先级分组控制**：由 SCB（System Control Block，系统控制块）中的 **AIRCR（Application Interrupt and Reset Control Register，应用中断和复位控制寄存器）** 的 `PRIGROUP[2:0]` 位控制。SCB 基地址 0xE000 ED00，AIRCR 偏移 0x0C，复位值 0xFA05 0000。写该寄存器必须在 `VECTKEY` 段写入 0x05FA，否则写操作无效。

**中断屏蔽寄存器（3 个，特权级访问）**：

| 寄存器 | 位宽 | 作用 |
| --- | --- | --- |
| PRIMASK | 1 位 | 置 1 关闭所有可屏蔽异常，只剩 NMI 和 HardFault 能响应；默认 0（允许中断） |
| FAULTMASK | 1 位 | 置 1 时只有 NMI 能响应，其余全部禁止；异常退出时自动清零 |
| BASEPRI | 最多 9 位 | 设定优先级阈值，优先级号 ≥ 该值的中断全部关闭；写 0 则不屏蔽任何中断 |

汇编中可用 `MRS`/`MSR` 操作 PRIMASK，或用更简洁的 `CPS` 指令：

```assembly
CPSID I    ; 关中断，PRIMASK = 1
CPSIE I    ; 开中断，PRIMASK = 0
CPSID F    ; 关异常，FAULTMASK = 1
CPSIE F    ; 开异常，FAULTMASK = 0
```

`BASEPRI_MAX` 与 `BASEPRI` 是同一寄存器的两种访问名，区别是 `BASEPRI_MAX` 只许把阈值设得更小（「许进不许出」），而 `BASEPRI` 可任意调整或解除屏蔽。

> 随堂小测（课件原题）：
> - 要屏蔽所有可屏蔽中断但保留 HardFault 和 NMI，应操作 **PRIMASK**（答案 B）；
> - FAULTMASK 置 1 后，仍能响应的是 **NMI**（答案 C）；
> - 「BASEPRI 设为阈值可屏蔽所有优先级号低于该阈值的中断」——判断题应为**错误**（应是「优先级号大于等于阈值」的中断被关闭，优先级数字越大优先级越低）。

### 2.4 中断系统设置过程

系统启动后配置中断的一般步骤：

1. 设置优先级分组寄存器（默认组 0）；
2. 若需重定位向量表，先把 HardFault 和 NMI 服务例程入口写进新表项；
3. 配置向量表偏移量寄存器指向新向量表；
4. 为该中断建立中断向量（读取偏移量，计算表项并填入口地址）；
5. 设置该中断的优先级；
6. 使能该中断。

对应汇编片段（设置分组、优先级、使能）：

```assembly
LDR  R0, =0xE000ED0C      ; AIRCR 地址
LDR  R1, =0x05FA0500      ; 写钥匙 0x05FA + 分组值
STR  R1, [R0]
LDR  R0, =0xE000E400      ; 优先级寄存器基址
MOV  R1, #0xC0
STRB R1, [R0, #7]         ; 设置第7号中断优先级
LDR  R0, =0xE000E100      ; SETENA 使能寄存器
MOV  R1, #(1<<7)
STR  R1, [R0]             ; 使能第7号中断
```

## 三、外部中断 / 事件控制器 EXTI

**EXTI（External Interrupt/Event Controller，外部中断 / 事件控制器）** 由 19 个（互联型产品为 20 个）产生事件 / 中断请求的边沿检测器组成。每个输入线可独立配置输入类型（脉冲或挂起）和触发事件（上升沿、下降沿或双边沿），并可独立屏蔽；挂起寄存器保存状态线的中断请求。EXTI 能检测脉冲宽度低于 APB2（Advanced Peripheral Bus 2，高速外设总线）时钟宽度的外部信号。

### 3.1 线路映像

| EXTI 线 | 功能描述 | 支持性 |
| --- | --- | --- |
| EXTI0 ~ EXTI15 | 供 GPIO 引脚使用，共 16 条（PAx、PBx、PCx、PDx、PEx 都映射到 EXTIx，x = 0~15） | 所有型号 |
| EXTI16 | 连接可编程电压检测器（PVD，Programmable Voltage Detector）输出 | 所有型号 |
| EXTI17 | 连接实时时钟（RTC，Real Time Clock）闹钟事件 | 所有型号 |
| EXTI18 | 连接 USB 唤醒事件 | 所有型号 |
| EXTI19 | 连接以太网唤醒事件 | 仅互联型（如 STM32F105/107） |

> 注意：通过 `AFIO_EXTICRx` 配置 GPIO 线上的外部中断 / 事件，**必须先使能 AFIO 时钟**（RCC_APB2ENR 位 0，`AFIOEN`）。

### 3.2 中断过程与事件过程

外部信号从引脚进入，经过如下通道产生**中断请求**：边沿检测电路 → 或门（另一输入是软件中断 / 事件寄存器）→ 挂起请求寄存器 → 与门 1 → NVIC。

4 个控制选项要点：

1. 边沿检测受**上升沿选择寄存器**和**下降沿选择寄存器**控制，两者独立，可同时选上升沿和下降沿（双边沿）；
2. 或门的另一个输入是软件中断 / 事件寄存器——软件可越过外部信号请求中断 / 事件，对应位写 1 即可；
3. 信号经或门后进入挂起请求寄存器，记录外部信号的电平变化；
4. 最后经与门 1 输出到 NVIC；若中断屏蔽寄存器对应位为 0，请求被屏蔽。

**事件产生过程**与中断类似，但在与门 2 处引出：事件请求经与门 2（由事件屏蔽寄存器控制），再由脉冲发生器把跳变信号转成单脉冲，输出给其它功能模块。

**中断与事件的关系**

从外部激励看，中断和事件没有分别，只是芯片内部分成两路：一路向 CPU 产生中断请求，另一路向其它模块发送脉冲触发信号。区别：

- **中断**：有事件产生并跳转到对应 ISR。可被更优先的中断屏蔽；
- **事件**：表示检测到触发事件发生。事件可触发中断，也可不触发；事件**不会**被屏蔽，本质是一个触发信号，用于唤醒内核或触发特定外设模块。

### 3.3 中断和事件的管理

要产生**中断**，需配置并使能中断线：设置 `EXTI_IMR`（中断屏蔽）开放中断请求，配置 `EXTI_RTSR`/`EXTI_FTSR`（上升 / 下降沿触发选择），并配合 NVIC 使能对应通道；期待边沿发生时产生中断请求、对应挂起位置 1，向挂起寄存器写 1 可清除。

要产生**事件**，类似地配置 `EXTI_EMR`（事件屏蔽）和触发选择位即可，但对应挂起位**不**被置 1。

软件中断 / 事件：在 `EXTI_SWIER` 写 1 也可产生中断 / 事件请求。

## 四、EXTI 相关寄存器

EXTI 寄存器首地址 **0x4001 0400**，所有 EXTI 寄存器必须以字（32 位）方式操作。位 19 仅适用于互联型产品，其它产品为保留位。

| 寄存器 | 偏移 | 复位值 | 关键位 |
| --- | --- | --- | --- |
| `EXTI_IMR` 中断屏蔽 | 0x00 | 0x00000000 | 位[19:0] MRx：0 屏蔽 / 1 开放中断请求 |
| `EXTI_EMR` 事件屏蔽 | 0x04 | 0x00000000 | 位[19:0] MRx：0 屏蔽 / 1 开放事件请求 |
| `EXTI_RTSR` 上升沿触发 | 0x08 | 0x00000000 | 位[19:0] TRx：允许上升沿触发 |
| `EXTI_FTSR` 下降沿触发 | 0x0C | 0x00000000 | 位[19:0] TRx：允许下降沿触发 |
| `EXTI_SWIER` 软件中断事件 | 0x10 | 0x00000000 | 位[19:0] SWIERx：写 1 置对应挂起位 |
| `EXTI_PR` 挂起 | 0x14 | 0xXXXXXXXX | 位[19:0] PRx：发生触发请求置 1；写 1 清除 |

## 五、中断相关库函数

### 5.1 NVIC 相关函数

`NVIC_PriorityGroupConfig(u32 NVIC_PriorityGroup)`：设置优先级分组（抢占与副优先级位数），**分组只能设置一次**。

`NVIC_Init(NVIC_InitTypeDef * NVIC_InitStruct)`：初始化 NVIC 寄存器。结构体定义在 `stm32f10x_nvic.h`：

```c
typedef struct {
    u8 NVIC_IRQChannel;                    // 使能 / 除能的 IRQ 通道
    u8 NVIC_IRQChannelPreemptionPriority;  // 抢占优先级值
    u8 NVIC_IRQChannelSubPriority;         // 副优先级值
    FunctionalState NVIC_IRQChannelCmd;    // ENABLE 或 DISABLE
} NVIC_InitTypeDef;
```

### 5.2 EXTI 相关函数

`EXTI_Init(EXTI_InitTypeDef * EXTI_InitStruct)`：初始化 EXTI 寄存器。结构体定义在 `stm32f10x_exti.h`：

```c
typedef struct {
    u32 EXTI_Line;                     // 选择的外部线路
    EXTIMode_TypeDef EXTI_Mode;        // EXTI_Mode_Interrupt 或 EXTI_Mode_Event
    EXTI_Trigger_TypeDef EXTI_Trigger; // Rising / Falling / Rising_Falling
    FunctionalState EXTI_LineCmd;      // ENABLE 或 DISABLE
} EXTI_InitTypeDef;
```

**例：将 EXTI_Line0 设为下降沿中断**

```c
EXTI_InitTypeDef EXTI_InitStructure;
EXTI_InitStructure.EXTI_Line    = EXTI_Line0;
EXTI_InitStructure.EXTI_Mode    = EXTI_Mode_Interrupt;
EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;
EXTI_InitStructure.EXTI_LineCmd = ENABLE;
EXTI_Init(&EXTI_InitStructure);
```

其它常用函数：

- `EXTI_GetITStatus(u32 EXTI_Line)`：检查指定 EXTI 线路触发请求是否发生，返回 SET/RESET；
- `EXTI_ClearITPendingBit(u32 EXTI_Line)`：清除 EXTI 线路中断挂起位；
- `GPIO_EXTILineConfig(u8 GPIO_PortSource, u8 GPIO_PinSource)`：选择 GPIO 引脚用作外部中断线路（`GPIO_PortSource_GPIOy`，y = A~E；`GPIO_PinSourcex`，x = 0~15）。

## 六、中断应用实例分析

外部中断应用编程的一般步骤：

1. **系统初始化**：如系统时钟初始化；
2. **GPIO 配置**：务必在打开 GPIO 时钟时一并打开 AFIO 时钟；
