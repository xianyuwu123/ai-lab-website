三个寄存器与影子寄存器：容易混淆的地方
软件访问当前硬件使用的内容写入后何时生效
TIM2_CNT
0x40000024		当前计数值直接改写 CNT，不需要等 UEV；不会因此产生 UEV。
TIM2_PSC
0x40000028		内部有效 PSC 值决定分频系数PSC 始终有缓冲，新值在更新事件时装载。ARPE 不控制 PSC。
TIM2_ARR
0x4000002C		内部有效 ARR 值决定计数上限ARPE＝1 时等 UEV；ARPE＝0 时不等待 UEV。

读到新值，不代表硬件已经使用新值。软件读 PSC、ARR 可看到刚写入的内容，但内部影子值可能仍旧不同。“预装载”和“影子”是同一个配置参数的两份存储，不是两个都要由程序员写地址的外设寄存器。

ARR 的“重装载”不是把向上计数的 CNT 反复写成 ARR。向上计数由 ARR 决定上限，越过上限时 CNT 回到 0；向下计数在下溢时把 ARR 装入 CNT。本页专讲向上计数。

PSC 寄存器与预分频器内部计数不是同一个东西。PSC 配置值保持不变，内部累计进度才随每个输入边沿变化。

UEV、UIF、CPU 中断是三件事。UEV 是硬件事件，UIF 是保持到软件清除的标志位；进入中断还需要 DIER.UIE、NVIC 等条件。动画的事件高亮只为回看当前一步，不表示 UEV 会持续为高。

上板时如何初始化？为什么要写 EGR.UG？

下面只展示 TIM2 时基初始化，前提是已开启 TIM2 外设时钟，且 TIM2 当前停止、未被其他功能使用。RCC 时钟树决定 fTIM，不能直接把 CPU 主频代入公式。

// 假设 TIM2 内部时钟为 72 MHz；配置成每 1 ms 更新一次
TIM2->CR1 = TIM_CR1_ARPE; // 停止、向上计数、ARR 预装载；UDIS=0，URS=0
TIM2->DIER = 0;          // 初始化期间关闭定时器中断 / DMA 请求
TIM2->PSC = 71;          // 写入预装载值：72 MHz / (71+1) = 1 MHz
TIM2->ARR = 999;         // 写入预装载值：1000 个计数节拍 = 1 ms
TIM2->EGR = TIM_EGR_UG;  // 装载有效 PSC、ARR；CNT 与预分频内部计数归零
TIM2->SR = 0;           // 初始化阶段清掉 UG 产生的 UIF 等标志
TIM2->CR1 |= TIM_CR1_CEN;

// 运行中平稳换周期：ARPE=1，下一次自然 UEV 后生效
TIM2->ARR = 1999;        // 从下一轮起，周期变成 2 ms

// 若要立即换参数并重新起算，可写 EGR.UG；会打断当前计数进程。
// 若要启用更新中断，还需 DIER.UIE、NVIC 与对应的中断服务函数。

运行中连续写 PSC 与 ARR 是两次软件写操作。若两次写之间恰好发生 UEV，可能分两次生效；例②把输入时钟暂停以便讲解，不能据此认为真实芯片的两次写入具有原子性。

官方依据与演示条件

依据 ST《RM0008》Rev 21，第 15.3.1 节 Time-base unit、第 15.3.2 节 Counter modes，以及 TIMx_CR1、TIMx_EGR、TIMx_CNT、TIMx_PSC、TIMx_ARR 寄存器说明。 官方参考手册； ST 技术人员对预装载与影子值的说明。链接需联网，页面动画自身可完全离线使用。

本页采用 STM32F1 TIM2、内部时钟、向上连续计数、CEN＝1、UDIS＝0、URS＝0，无外部触发、DMA 或重复计数器。省略总线写入与硬件同步延迟，ARPE＝0 的“立即”表示不等更新事件，不代表物理上没有传播时间。

所有例子从已初始化好的教学状态开始；真实复位后的 PSC、ARR 不等于这些示例值。例③用增大 ARR 演示即时更新，避免把运行中的 ARR 改到小于当前 CNT 所引出的额外边界情形。
